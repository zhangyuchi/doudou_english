# 第三方在线英音服务调研

核验日期：2026-09-29。本文供项目维护者判断是否增加第三方在线语音来源，记录调研结果和候选方向；在线播放尚未接入项目。

## 结论

浏览器直接播放第三方提供的 MP3 在技术上可行，可以减少对设备安装的系统语音的依赖。一次播放成功不能证明服务允许第三方网站免费接入，也不能证明不限流、长期可用、真人英音或所有操作系统兼容。

本次用有道的一个词语发音链接做了小规模验证：HTTP 请求成功，Chromium 中直接通过 `<audio>` 播放并正常结束；同一页面使用 `fetch` 读取失败。当前项目通过 `fetch` 获取音频并解码，因此不能只替换资源地址来完成接入。

建议将在线语音作为可选来源，保留预置音频。接入前核对服务许可，完成目标词表和真实 iPad Safari 验证。本文没有把候选方案作为已经采纳的设计决策。

## 已验证的请求与播放结果

测试请求地址：

```text
https://dict.youdao.com/dictvoice?audio=without&type=1
```

该地址是本次观测样本，不是已确认获准接入的免费公开 API。没有凭 `type=1` 参数断言录音为真人英音。

| 检查                                       | 本次结果                                          | 能证明的范围                                             |
| ------------------------------------------ | ------------------------------------------------- | -------------------------------------------------------- |
| 单次 HTTPS GET                             | HTTP 200，`Content-Type: audio/mpeg`，11,302 字节 | 当时能取得该词的音频响应                                 |
| Chromium 中点击按钮，调用 `<audio>.play()` | `played: true`，随后 `ended: true`                | 浏览器成功启动播放并收到结束事件，未人工验收听感         |
| 同页调用 `fetch`，尝试读取音频             | `TypeError: Failed to fetch`                      | 该次脚本读取失败，不能直接复用项目现有加载方式           |
| 响应头检查                                 | 未看到 `Access-Control-Allow-Origin`              | 未观测到允许脚本跨域读取的响应头；不是完整的故障归因排查 |

浏览器验证使用项目已安装的 Playwright Chromium，从测试页面 `http://127.0.0.1:19878/` 点击按钮播放。页面由 Playwright 路由返回；没有修改项目或启动新的业务服务。此次只有 `without` 一个样本，没有测试 161 项词/短语的覆盖、连续听写、长期访问或高频请求。

可重新检查单次 HTTP 请求：

```bash
curl -L --max-time 20 -sS \
  -D /tmp/doudou-dictvoice.headers \
  'https://dict.youdao.com/dictvoice?audio=without&type=1' \
  -o /tmp/doudou-dictvoice.mp3
```

这个命令只验证请求与响应，不能替代浏览器、真实设备或授权核验。外部服务可能变化，复测结果应记录实际时间。

## `<audio>` 与当前加载方式的区别

[当前音频驱动](../src/audio.js)使用 `fetch` → `arrayBuffer` → `AudioContext.decodeAudioData` → 播放解码后的音频，并维护最多 32 项的解码缓存。跨域 `fetch` 需要对方返回合适的跨域许可响应头；使用 `no-cors` 会得到脚本无法读取的响应，不能用于该解码流程。[MDN：跨域 Fetch 与不透明响应](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)

普通 `<audio src="第三方音频地址">` 在未设置 `crossorigin` 时采用不同的资源加载方式，某些脚本不能读取的跨域音频仍可直接播放。但它仍受资源访问控制、浏览器策略及服务方限制影响；若进一步将媒体接入 Web Audio 处理，也不能忽略跨域要求。[MDN：audio 元素](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/audio)、[Web Audio 加载说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Using_Web_Audio_API)

音频来自第三方也仍受自动播放规则约束。首次播放应由用户点击触发，并处理 `play()` 被拒绝的情况；连续换词、暂停恢复和切后台后的行为需在目标 Safari 版本上验证。本次 Chromium 结果不是 iPad Safari 的实机兼容证据。[MDN：自动播放限制](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

## 免费网页链接与正式 API 的使用条件

本次没有找到上述 `dictvoice` 链接承诺允许第三方网站免费接入、不限量访问、永久可用或提供完整英音真人词库的官方文档。因此应将它视为当前可访问的网页发音地址，不能作为长期服务承诺。

有道正式词典 API 是另一项服务。[官方词典 API 文档](https://ai.youdao.com/DOCSIRMA/html/dictionary/api/ydcd/index.html)说明它输出释义、发音、音标和例句，接入需联系商务，暂不支持控制台自助开通，并明确禁止缓存、再利用和转卖返回数据。该 API 文档不能被当作 `dictvoice` 免费网页地址的接入许可，也不能直接拿来判定两者有相同使用条件。

如果改用正式服务，需核对具体授权是否允许网页播放、短期内存缓存、重复播放及本地保存。不能默认沿用当前预置音频的缓存政策，也不能把需要保密的 API 密钥放进浏览器代码。

## 对当前项目的候选改造方向

以下为待评估建议，尚未实现：

- 增加明确命名的“在线英音”来源，说明需要网络，避免把未经核验的声音标成高质量真人录音。
- 使用适合服务条件的加载方式；若采用媒体元素直连，优先复用同一个元素，并在用户点击中启动播放。
- 播放结束后再启动下一遍或下一词的等待；加载超时、播放拒绝或资源缺失时显示错误，不能把未播放当作已经完成。
- 暂停、换词、试听和切换来源时取消旧播放，防止迟到的事件推动错误的听写队列。
- 保留预置音频，由用户明确切换备用来源；不静默改变发音来源或跳过失败词条。

具体接口、超时值和恢复行为应在获准实施后设计。直连能将音频请求交给用户浏览器，但网络延迟、登录要求、防盗链、限流和地址变更仍可能影响使用，且没有离线播放保证。

## 验证边界与后续维护

已验证：一个有道音频地址的 HTTP 响应、Chromium 点击播放及结束事件、同页 `fetch` 失败、当前项目加载与缓存方式，以及上述官方资料中的接入条件。

未验证：真实 iPad Safari 和其他系统、全部词条及短语、英音真人来源与听感、连续播放和取消恢复、长期稳定性、免费第三方接入许可、不限流及服务保障。本次没有接入在线服务、购买套餐、联系供应商或修改播放器。

服务条款、地址、权限或浏览器版本变化后，应重新核验；正式实施前也应复测上述未确认事项。当前预置音频的来源和使用方式见[预置英音](audio.md)。
