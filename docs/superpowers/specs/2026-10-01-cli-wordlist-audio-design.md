# 本地词表与阿里云音频一键发布

Task Mode: design-build。Outcome Status: complete（代码、模拟及本机真实 API 验证范围）。日期：2026-10-01。

## 目标与证据

原始需求：本地命令读取 TXT、CSV 或 PDF 词表，向阿里云生成声音，自动导入网站；命令完成后刷新网页即可看到新词并播放英音。

目标范围是本项目在同一电脑上运行的 Vite 开发服务，或本地静态 `dist` 服务。命令在成功后重建 `dist`；远程站点仍需把新产物发布到远端，因为本地文件不能改变远端服务器。成功信号：三种格式解析为同一词表；仅缺失项向阿里云请求；所有项有音频后原子发布词表；网页刷新加载新清单并选中阿里云英音。扫描 PDF、真实阿里云账号授权和自动远程部署不在本次范围。

Evidence Snapshot（`17671c4`，2026-10-01）：`src/import.js` 有 TXT/CSV/PDF 解析及 `makeSource`；Node 中 PDF.js 与 `extractPdfGroups` 可从项目样例得到 11 组 161 项。`generateAudio` 已提供凭证隔离、逐项原子落盘和断点复用。`vite.config.js` 在启动/构建时嵌入私有清单，故当前刷新不能取得新声音。`storage.js` 只保存一份当前词表和错词；损坏快照须显式恢复。以上不能证明第三方真实合成或任意 PDF 排版。

操作者是本机维护者，学习者在浏览器使用词表。输入文件由维护者提供；真实合成可能收费。已知运行环境 Node 22.13+、Vite 静态资源目录和同站 WAV 驱动。未知：账号权限、网络、实际音质、用户最终采用本地或远程托管；远程场景按显式发布边界处理。

## 概念、逻辑与决定

词表源是含分组和每项独立 ID 的完整快照。音频清单以规范化英文为键，同一英文只合成一份；词表里的重复出现仍为不同项。发布文件 `public/audio/aliyun/active-list.json` 是命令成功提交的当前词表，`manifest.json` 是已成功音频索引；二者不包含凭证，所在目录已被 Git 忽略。浏览器本地快照保存设置、当前源、错词以及最后应用的命令行源 ID。

- LC-1：因为网页不能直接读取命令进程或跨浏览器 localStorage，所以命令在同站静态目录发布词表，网页刷新时读取它。
- LC-2：因为现有清单嵌在前端包中，刷新无法取得新文件，所以阿里云清单改为运行时读取；预置音频仍按原方式加载。
- LC-3：因为合成可能失败或中断，所以命令先复用或生成并验证全部音频，再原子替换 `active-list.json`；失败保留旧词表。
- LC-4：因为手动切回内置词表应保持有效，所以浏览器只在命令发布了新的源 ID 时自动切换，并清空旧源错词；同一源的刷新保留错词。

Decision Log：选择运行时 JSON 发布。替代 A 是继续手动浏览器导入，操作不满足刷新目标；替代 B 是 CLI 写浏览器存储，不能跨浏览器且需要控制浏览器进程。若未来引入后端账户同步，再重新评估。高级检查选择持久化、发布顺序、兼容性和凭证隔离；现有播放器状态机不改。

## 数据、处理与错误契约

命令 `npm run import:aliyun -- --input <path> [--execute]`；默认仅预览，无网络或写入。`--execute` 才合成并发布。TXT/CSV 复用既有解析；文字版中英 PDF 在 Node 中用现有 PDF.js 和同一 `extractPdfGroups` 解析。文件限制与网页一致：20 MB、PDF 100 页、2000 项。单组超过 15 项时沿用网页默认重新分组。标题来自输入文件名。

用户补充：`--input` 可省略。此时在持有发布锁后读取 `active-list.json`，不存在则使用内置词表；沿用 `manifest.json` 的音色与语速，默认 Emily/0。损坏的发布文件报错，不触发内置回退。词表结构验证独立于音频覆盖验证，允许修复缺失音频；将项 ID 去除后按原内容计算发布 ID，保持错词记录。网页手动导入的 localStorage 数据不能由 CLI 读取。验证覆盖内置预览、已发布词表修复、缺失与损坏文件、配置继承、无凭证复用、坏词表禁止请求。

发布源 ID 由词表内容和标题哈希生成。命令先完成 `generateAudio`，复核全部词都在清单中，再原子写入 `active-list.json`。静态 `dist` 由 Vite 独占生成，命令调用项目既有 build，不直接写 `dist`。现有音频文件和清单的逐项恢复规则不变。

真实调用发现：HTTP 200 的 `without` WAV 实际为 23082 字节，标准 PCM 头的 RIFF/data 长度却分别声明 153636/153600。与[阿里云官方 FAQ](https://help.aliyun.com/zh/isi/support/faq-about-speech-synthesis)中流式 WAV 头使用预估长度一致。修复边界：仅对完整收到的 HTTP 成功音频响应、标准 44 字节 PCM WAV 头且声明长度互相一致的情况，将 RIFF/data 长度更新为实际字节数，随后按原严格校验落盘。保存后的文件复用不执行修复；非标准头、非法 PCM 参数、半个采样帧、响应读取失败仍拒绝。此修复不改变输出格式或清单 schema。新增回归须覆盖预估长度大于/小于实际、音频样本不变、磁盘截断重新生成和非法响应拒绝。审查采用本地完整检查；当前未提供独立审查技能。

命令在付费生成、词表提交和构建期间持有独立的 `.import.lock`；已有音频生成器继续独占 `.generate.lock`。同时运行两次词表命令时，后者在调用服务前失败。正常退出清理锁，异常断电后的锁由操作者确认进程结束后手动清理。

网页使用 `cache: no-store` 读取同站 JSON。没有私有清单时维持预置英音；没有发布词表时维持当前词表。清单或词表格式错误时保留本地状态并显示错误。命令词表仅在私有清单覆盖全部项时自动应用；旧版本本地快照可读取，损坏快照不被自动覆盖。新源 ID 应用时清空旧错词并选中阿里云英音；手动切回内置或导入其他词表后，同一源 ID 不再强制覆盖。新的命令行词表 ID 会再次自动应用。
