原始需求是提供自有服务器部署脚本与操作文档。目标是维护者可配置一次服务器参数，随后用明确命令发布、列出版本和回滚；学生可按文档在 iPad 导入自己的词表。成功信号为脚本通过本地模拟远端验证、发布切换完整版本、失败不改变当前版本、文档命令与实现一致。错误行为包括上传未完成就切换、覆盖无关目录、隐藏 SSH 失败或误称已完成真实部署。

非目标：自动安装或管理 Web 服务、自动修改防火墙/DNS/证书、实际生产发布、自动删除历史版本、云语音、GitHub Actions、Docker 和浏览器导入功能变更。

补充确认：用户提出使用 Python 内置 Web 服务。文档将增加 Python 3.9+ 的 http.server 作为可信内网或临时试用方案，不要求安装 Nginx/Caddy。Python 官方明确不推荐 http.server 用于生产环境（https://docs.python.org/3/library/http.server.html）；公网正式服务仍推荐专门的静态 Web 服务。示例只提供 current 目录，不能提供仓库或部署根目录；监听地址与防火墙范围需明确。不会因为使用 Python 而改变发布脚本或生成额外 Python 服务程序。

## 工作模型、依赖与约束

家长/维护者在 Linux 或 macOS 电脑发布，学生用 iPad 浏览网站。电脑已有项目要求的 Node.js >=22.13、npm，以及 ssh、tar；首次运行 npm ci。远端假设有 Bash、GNU coreutils（含 mv -T）、tar、gzip；Web 服务能读取部署文件及跟随 current 链接。Windows 用户可使用 WSL，原生 PowerShell 不属于本脚本承诺范围。

SSH 通过已有 OpenSSH 配置或 SSH 密钥认证；脚本不保存密码、不关闭主机密钥检查、不使用 sudo。真实服务器工具与权限由维护者按文档检查，未验证时不宣称支持该服务器。

脚本仅负责显式指定的应用专用目录，例如 /srv/doudou-english。不接受 /、/srv、/var、/var/www、/home 或用户家目录本身；路径采用受限的绝对路径字符与非空段，拒绝空格、shell 元字符及 . / .. 段。远程路径引用与参数验证同时使用，不能把配置值当 shell 代码执行。

## 概念空间与逻辑链

部署根目录是此应用专用的远端目录；release 是一次完整 dist 的版本目录；current 是 Web 服务固定访问的符号链接；发布锁是对同一根目录的互斥锁。浏览器词表和错词仍是 localStorage 数据，不属于服务器版本目录。

LC-1：因为项目只交付静态 dist，所以服务器只需提供静态文件，部署不绑定 Nginx 或 Caddy。
LC-2：因为上传会失败或中断，所以每次写独立 release，完整解包并检查 index.html 后才允许切换 current。
LC-3：因为切换与回滚会竞争，所以两者共享远端发布锁，并通过同目录临时链接加原子 rename 更新 current。
LC-4：因为远程命令能改动服务器，所以配置受限、参数引用、SSH 默认安全检查及专用目录所有权校验必须是发布边界，而不能仅靠使用者谨慎。
LC-5：因为浏览器导入和服务器发布互不依赖，所以导入指南独立说明本地文件读取和保存行为，不引入上传接口。

## 决策与架构判断

DEC-1：采用本地 npm build 加 SSH 传送压缩归档；拒绝服务器 git pull 构建，避免远端 Node.js 与源码权限依赖。若将来需要持续集成，再评估构建执行位置。

DEC-2：采用 release/current；拒绝直接覆盖站点目录，避免暴露半成品与删除无关文件。历史版本默认全部保留；磁盘压力由维护者按指南人工处理，不增加自动清理机制。

DEC-3：采用 JSON 配置文件与 Node.js 命令入口，远端使用小型 Bash 发布程序；避免 source 配置、第三方部署依赖及额外服务。配置样例可提交，真实本地配置被 Git 忽略。

主线是发布和回滚，配置示例与诊断服务主线；Web 服务安装、HTTPS 管理、浏览器存储与声音质量属于正交边界。不能为缩短脚本而直接覆盖 current 所指的文件。

Selected Check IDs: AA-DELIVERY、AA-RUNTIME。

AA-DELIVERY：完整 dist 是唯一发布单元，包含 PDF worker、字体、样例 PDF。旧 release 可回滚，但不会恢复或迁移浏览器记录。部署路径与网页 origin 不变时现有记录仍按当前存储契约使用。

AA-RUNTIME：本地构建和 SSH 子进程必须检查退出码；远端单次会话持有发布锁，互斥保护创建版本和切换。无法自动回收进程被强制杀死后留下的锁；文档说明确认无发布进程后人工解除。

## CLI、目录与错误契约

拟定入口：npm run deploy -- --config deploy.config.json；支持 --dry-run、--list 和 --rollback VERSION。默认操作构建并发布；dry-run 只验证配置并展示计划，不构建、不 SSH、不改变文件。list 只读取已有发布根目录，不创建目录或锁。

配置字段：host（SSH 主机名或已有 Host 别名）、user（可选，留空使用 SSH 配置）、port（可选整数 1—65535）、remoteDir（必填专用绝对路径）。私钥路径、ProxyJump 等由 ~/.ssh/config 管理，不在项目复制凭据。

远端布局：remoteDir/releases/VERSION、remoteDir/current、remoteDir/.deploy-lock，以及识别该布局的应用标记文件。VERSION 由本地生成的时间与随机后缀组成，只包含字母、数字、点、下划线和连字符。回滚只接受合法的已有版本目录。

首次发布仅接管空目录并建立标记；非空未标记目录拒绝。已有标记目录必须校验 releases/current 的预期类型与链接目标，不能跟随被替换的发布目录链接去写其他目录。current 是非链接文件或目录时拒绝覆盖。并发发布遇到锁立即失败，不盲目等待或删除锁。

处理顺序：配置验证 → 本地构建 → 本地临时归档 → SSH 远端校验与加锁 → 新版本解包 → index.html 检查 → 临时链接创建 → 原子切换 → 释放锁。任一步失败返回非零退出码；current 在切换前保持原样。失败版本目录可以保留供诊断，临时归档在本地 finally 清理。SSH 中断若发生在切换之后，结果可能已发布但本地未收到确认，应通过 list/current 与 HTTP 检查确定，不自动重试覆盖。

回滚共享校验、锁和原子切换，不重新构建、不上传。不存在、非法或被篡改成符号链接的版本拒绝。脚本不自动发起 HTTP 健康检查，也不改变 Web 服务；成功只表示完整文件版本已切换，网页可访问性需按文档验证。
